Build timeWhat Siri knows before you speak

Siri never reads Skyway's Swift code. When Xcode builds the app, it extracts a description of every tool and compiles the skill. That's what's installed on the phone and what Siri works from.

  • AvailableSeat, Seat.Position
  • Skills.skillsbundle
→
Inside Skyway.app
  • Metadata.appintents/extract.actionsdata: titles, descriptions, parameters
  • Metadata.appintents/Skills.skillsc: the compiled skill
→
On the iPhone
  • Siri sees 3 tools from Skyway
  • and 1 skill: seat-selection, known by its description
Why the metadata matters so much Siri decides what to call from text alone: the tool's title and description, each parameter's description, and the skill's description. That's why those strings are written for a reader who has never seen the app. Apple's sirimetadataanalyzer checks them; Skyway's build reports 13 intents, 3 tools, 0 errors, 0 warnings.

Step by stepEach step in detail

1
Person → Siri

“In Skyway, get me a window seat with more legroom”

Saying “In Skyway” matters. Apple's rule is that Siri can call an app's tools when the request names the app, when the app is on screen, when it has a Live Activity running, or when one of its entities came up in search. Here the name does it.

There's no seat number in the request, so no single tool can do the job directly. Change Seat needs an exact seat like “12F”. This is the situation the skill was written for.

2
Siri

Siri looks at what Skyway offers

It has Skyway's three tools, each described by its metadata, and one skill, known only by its description at this point:

ToolFrom its description
Get Available Seats“Lists free seats … closest to your current seat first, with each seat's position and any extra-legroom fee. It doesn't change your seat.”
Change Seat“Moves you to a different seat on your upcoming Skyway flight after you confirm. Extra legroom seats in rows 12 and 15 cost $49.”
Create InvoiceNot relevant to this request.
3
Siri → seat-selection skill

The skill is chosen by its description alone

Apple's rule: the system reads only the description to decide whether a skill applies. So it's written in the words a person would use, and says what it's not for:

App/Skills.skillsbundle/Skills/seat-selection/SKILL.md · frontmatter---
name: seat-selection
description: Choose a new seat on the user's upcoming Skyway flight when they
  describe the kind of seat they want instead of a seat number, such as a
  window or aisle seat, more legroom, an exit row, or a seat near the
  front. Also for asking which seats are free. Not for questions about the
  gate, boarding time, or trip details.
---

Three phrases line up with the request, so this skill is picked. The name has to match the folder name, seat-selection, or the build fails.

4
seat-selection skill → Siri

The skill's instructions are handed to Siri along with the tools

Only now does Siri read the body. These are the lines that steer this request (highlighted):

SKILL.md · body (excerpt)If the user named an exact seat, like 17B, use the Change Seat tool with it.

Otherwise, use the Get Available Seats tool before changing anything, with
filters that match what the user asked for:

- "Window" or "aisle" sets the position. Never offer a middle seat …
- "More legroom", "extra legroom", "exit row", or "bulkhead" means
  extra-legroom seats only.
- "Near the front" or "closer to the front" means up to row 10.

If one seat clearly fits best, suggest it. If several fit equally well,
offer up to three and let the user choose.

Extra-legroom seats cost $49. Before choosing one, tell the user the price
and wait for them to agree, unless they already said they're happy to pay.

When the user has agreed on a seat, use the Change Seat tool with it.
Change Seat shows its own confirmation, so don't ask … a second time.
The skill only refers to tools by their titles It says “the Get Available Seats tool”, never GetAvailableSeatsIntent. Apple's guidance: Swift type names aren't part of what Siri sees, and titles are what keep working.
5
Siri → Get Available Seats

Siri fills the tool's values from the request

Siri's model turns words into parameter values, guided by the skill and each parameter's description:

App/Siri/Tools/GetAvailableSeatsIntent.swiftstruct GetAvailableSeatsIntent: AppIntent {
  static let title: LocalizedStringResource = "Get Available Seats"

  @Parameter(title: "Position", description: "Only window, middle, or aisle seats. Leave empty for any position.")
  var position: Seat.Position?                 // ← .window

  @Parameter(title: "Extra Legroom Only",
             description: "Only extra-legroom seats, in rows 12 and 15, which cost $49 more.",
             default: false)
  var extraLegroomOnly: Bool                      // ← true

  @Parameter(title: "Up to Row", description: "Only seats in row 1 through this row, for seats near the front. …",
             inclusiveRange: (1, 30))
  var maximumRow: Int?                            // ← nil
  // …trip
}

6
Get Available Seats → SeatMap

Skyway's code finds the matching seats

perform() runs inside Skyway's process, often in the background with no screen. It sorts free seats by distance from the current seat, then applies the three filters:

GetAvailableSeatsIntent.perform()let seatMap = SeatMap.forTrip(booking)
let current = Seat(booking.seat) ?? Seat(row: 1, letter: "A")   // 14A

let seats = seatMap.freeSeats(near: current, excluding: current, limit: .max)
  .filter { position == nil || $0.position == position }        // window: A or F
  .filter { !extraLegroomOnly || seatMap.fee(for: $0) != nil }  // rows 12 and 15
  .filter { $0.row <= (maximumRow ?? .max) }
  .prefix(Self.resultLimit)                                     // at most 8
  .map { AvailableSeat(seat: $0, map: seatMap) }

7
Get Available Seats → Siri

The result goes back to Siri, not straight to the person

The tool returns two things. Siri's model reads both and decides what to say next.

GetAvailableSeatsIntent.perform()return .result(
  value: seats,      // [AvailableSeat] — structured, for the model
  dialog: "You're in \(booking.seat). Free seats nearby on flight \(booking.flightNumber): \(list.formatted(.list(type: .and)))."
)
// → value:  [ AvailableSeat(seat: "12F", row: 12, position: .window, isExtraLegroom: true, fee: 49) ]
// → dialog: "You're in 14A. Free seats nearby on flight SW 214: 12F (window, $49)."
App/Siri/Entities/AvailableSeat.swiftstruct AvailableSeat: TransientAppEntity {
  @Property(title: "Seat") var seat: String
  @Property(title: "Row") var row: Int
  @Property(title: "Position") var position: Seat.Position
  @Property(title: "Extra Legroom") var isExtraLegroom: Bool
  @Property(title: "Fee") var fee: Int
}

Transient means it's a value made up on the spot, not something Siri can look up again later. A free seat is only a snapshot, so that fits.

8
Siri → Person, following the skill

One clear match, but it costs money, so Siri asks

Two skill rules apply: “If one seat clearly fits best, suggest it” and “Before choosing [an extra-legroom seat], tell the user the price and wait for them to agree”. Asking for “more legroom” isn't the same as agreeing to pay, so Siri asks:

💬 “12F is the only window seat with extra legroom on flight SW 214, and it costs $49. Do you want it?” → “Yes”

Without the skill, Siri might have called Change Seat straight away, or chosen a non-legroom window seat. Every tool would still have worked; the skill just makes the choice match what Skyway wants.

9
Siri → Change Seat

Siri calls Change Seat with the agreed seat

The seat came from Get Available Seats' result, as the skill requires (“Don't use the Change Seat tool with a seat that Get Available Seats didn't return”).

App/Siri/Tools/ChangeSeatIntent.swift@Parameter(title: "Seat",
           description: "The new seat, a row number from 1 to 30 followed by a letter from A to F, like 17B",
           requestValueDialog: "Which seat would you like?")
var seat: String     // ← "12F"
10
Change Seat → SeatMap

Change Seat checks the seat again

A tool must work on its own, with or without a skill, so Change Seat doesn't trust that the seat is free. It checks it exists, isn't the current seat, and isn't taken. Each failure is an error Siri can read and act on.

ChangeSeatIntent.perform()guard let newSeat = Seat(seat), seatMap.contains(newSeat) else {
  throw SeatChangeError.invalidSeat(seat.uppercased(), flight: booking.flightNumber)
}
guard newSeat != current else { throw SeatChangeError.alreadyInSeat(newSeat.description) }
guard seatMap.isFree(newSeat) else {
  throw SeatChangeError.seatTaken(newSeat.description, nearby: seatMap.freeSeats(near: newSeat, excluding: current))
}
11
Change Seat → Person

Skyway's own confirmation card

perform() pauses on requestConfirmation. The card shows 14A Window → 12F Window and the $49 fee. The skill told Siri not to ask a second time, so this is the only confirmation.

ChangeSeatIntent.perform()try await requestConfirmation(
  actionName: .custom(acceptLabel: "Change Seat", acceptAlternatives: ["Yes", "Confirm", "Change it"],
                      denyLabel: "Keep \(booking.seat)", denyAlternatives: ["No", "Cancel"],
                      destructive: false),
  dialog: confirmationDialog(from: booking.seat, to: newSeat, fee: seatMap.fee(for: newSeat)),
  // "Move from 14A to 12F, an extra legroom window seat, for $49?"
  snippetIntent: SeatChangeConfirmationSnippetIntent(trip: booking.entity, newSeat: newSeat.description)
)
The card may not appear with Siri AI Apple's documentation notes that when the new Siri runs an app's intent, it might not display the app's dialog or card. The confirmation still happens; Siri may ask in its own words instead. From Shortcuts or the classic “Change my seat in Skyway” phrase the card always shows.
12
Change Seat → saved seat

The seat is saved

ChangeSeatIntent.perform() → App/SeatAssignments.swiftlet previousSeat = await SeatAssignments.changeSeat(of: booking, to: newSeat)
// UserDefaults "seat.K7QX2P" = "12F", then the trip is re-indexed in Spotlight

Because it's saved, the boarding pass, Flight Status, CarPlay and the in-app assistant all show 12F the next time they draw, even if Skyway wasn't open.

13
Change Seat → Siri → Person

The result, and Siri's last words

What if…Other ways the same flow goes

“In Skyway, get me a window seat”Get Available Seats → Change SeatPosition Window only. Several free window seats (14F, 13A, 13F…), so Siri offers up to three and lets the person pick.

BoundariesWhat's Skyway's code and what's Siri's

Skyway decides

  • Which tools exist, and their titles and descriptions
  • What each tool returns and every error message
  • Which seats are free and what they cost
  • The confirmation card, the saved seat, and the final sentence
  • The skill's guidance: look first, ask about the fee, offer choices, don't confirm twice

Siri decides

  • Whether the request is for Skyway, and whether the skill applies
  • Turning “more legroom” into Extra Legroom Only = on
  • The order of calls and how it phrases its questions
  • Whether to show the app's card or speak instead

How Siri matches skills and tools internally isn't public. This guide describes the behavior Apple documents for Xcode 27.3.

Testing it Siri AI and skills need a real iPhone with Apple Intelligence on iOS 27.3. In the simulator, tools still work through Shortcuts and Spotlight, but the skill isn't used. To check the skill shipped, look for Skyway.app/Metadata.appintents/Skills.skillsc in the build.
