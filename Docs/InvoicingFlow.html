Step by stepEach step in detail

1
Person → Siri

“In Skyway, bill John the usual”

Naming Skyway lets Siri use Skyway's tools. The request has three gaps that Create Invoice can't fill by itself:

Create Invoice needsThe person saidGap
Client“John”Only a first name. Which John?
Service(nothing)Missing
Amount“the usual”Means something only the history knows

Without help, Siri would ask “What's the invoice for?” and “How much should I bill?”, or worse, guess. The skill exists so it can work these out instead.

2
Siri

Siri looks at what Skyway offers

ToolFrom its description
Get Recent Invoices“Lists your most recent Skyway invoices, newest first, with each one's number, client, service, amount, and the date it was issued. It doesn't create or change invoices.”
Create Invoice“Creates an invoice in US dollars that bills a client for a service, after you confirm. It's due in 14 days.”
Get Available Seats, Change SeatNot about billing.
3
Siri → invoicing skill

Which skill? Only the descriptions decide

Siri compares the request with each skill's description. The body isn't read at this point.

invoicing ✓ chosen

Bill a client in Skyway when the request is
vague or missing details, such as no amount,
the usual amount, the same as last time, a
rate per hour or per visit instead of a total,
only a first name, or several jobs at once.
Also for asking what was billed recently. Not
for changing seats, trips, or mileage.

seat-selection ✗

Choose a new seat on the user's upcoming
Skyway flight when they describe the kind of
seat they want instead of a seat number, …
Not for questions about the gate, boarding
time, or trip details.

Each description ends with what it's not for. That's Apple's advice for keeping two skills in one app from being confused.

4
invoicing skill → Siri

The skill's rules arrive with the tools

Now Siri reads the body. These lines apply to “bill John the usual” (highlighted):

App/Skills.skillsbundle/Skills/invoicing/SKILL.md · body (excerpt)When the user gave a client, a service, and a total in dollars, use the Create Invoice tool
right away.

When anything is missing or vague, use the Get Recent Invoices tool first and fill in what you
can from it:

- **Client.** If the user gave only a first name and exactly one recent client has that first
  name, use that client's full name as it appears on the invoice. If several do, ask which one.
- **Amount.** For "the usual", "same as last time", or no amount at all, use the amount of the
  most recent invoice for that client and service, and tell the user which invoice it came from,
  by number and date. If there's no earlier invoice to go on, ask for the amount. Never guess one.
- **Rate and quantity.** For a rate and a count, like 3 walks at $40 …
- **Service.** If the user didn't say what it's for and every recent invoice for that client is
  for the same service, use that service and say so. Otherwise ask.

Before creating, check the recent invoices for one with the same client, service, and amount
issued today. If there is one, tell the user and ask whether they really want a second one.

Create Invoice shows its own confirmation, so don't ask the user to confirm a second time.
5
Siri → Get Recent Invoices

A lookup with no parameters

Apple's guidance is not to write search tools that take criteria. Siri finds things itself. So this tool simply returns the latest invoices, and Siri does the matching.

App/Siri/Tools/GetRecentInvoicesIntent.swiftstruct GetRecentInvoicesIntent: AppIntent {
  static let title: LocalizedStringResource = "Get Recent Invoices"
  static let description = IntentDescription(
    "Lists your most recent Skyway invoices, newest first, with each one's number, client, service, amount, and the date it was issued. It doesn't create or change invoices.",
    searchKeywords: ["invoices", "past invoices", "billing history", "last invoice", "what did I bill", "clients"]
  )

  /// How many invoices to report, so the answer stays short enough to read out.
  static let resultLimit = 10
}

@available(iOS 27.3, *)
extension GetRecentInvoicesIntent: ToolIntent {}
6
Get Recent Invoices → InvoiceStore

Skyway reads its saved invoices

perform() runs in Skyway's process, usually in the background, and reads the same store the app and Create Invoice use:

GetRecentInvoicesIntent.perform()let invoices = Array(InvoiceStore.invoices.prefix(Self.resultLimit))   // newest first
guard !invoices.isEmpty else {
  return .result(value: [], dialog: "You haven't created any invoices in Skyway yet.")
}
7
Get Recent Invoices → Siri

Structured invoices go back to Siri

GetRecentInvoicesIntent.perform()return .result(
  value: invoices.map(\.entity),      // [InvoiceEntity], for the model
  dialog: "Your recent invoices: \(list.formatted(.list(type: .and)))."
)

Each InvoiceEntity carries the fields the skill's rules need. Issued was added for this skill: without it, Siri couldn't say “on Oct 24” or spot a duplicate from today.

App/Siri/Entities/InvoiceEntity.swift@Property(title: "Number") var number: String      // INV-0006
@Property(title: "Client") var clientName: String  // John Carter
@Property(title: "Service") var service: String    // Gardening
@Property(title: "Amount") var amount: Double     // 450
@Property(title: "Issued") var createdAt: Date    // Oct 24 — new
@Property(title: "Due Date") var dueDate: Date
8
Siri, following the skill

Siri fills each gap from the history

This is reasoning, not Skyway code. Siri applies the skill's rules to the list it got back:

NumberClientServiceAmountIssued
INV-0007Maria LopezDog walking$120.00Nov 5
INV-0006John CarterGardening$450.00Oct 24
INV-0005Ana ParkLogo design$800.00Oct 20
“John”Exactly one recent client named John → John Carter (rule: use that client's full name) Service?Every invoice for John Carter is gardening → Gardening, and say so “the usual”Most recent invoice for John Carter and gardening → $450, from INV-0006 on Oct 24, and say which Duplicate?Nothing for John Carter issued today (Nov 9) → go ahead

So Siri tells the person where the numbers came from: “John Carter's last invoice, INV-0006 on Oct 24, was $450 for gardening.” It doesn't stop to ask, because Create Invoice's card is the confirmation.

10
Create Invoice

Create Invoice still checks everything itself

Apple's rule: every tool must work without a skill. Create Invoice doesn't assume Siri got it right:

CreateInvoiceIntent.perform()let client = clientName.trimmingCharacters(in: .whitespacesAndNewlines)
let work = service.trimmingCharacters(in: .whitespacesAndNewlines)
guard !client.isEmpty else { throw InvoiceError.missingClient }    // "An invoice needs a client name, like John."
guard !work.isEmpty else { throw InvoiceError.missingService }    // "…a service to bill for, like gardening."
guard amount > 0 else { throw InvoiceError.invalidAmount }      // "The amount needs to be more than $0…"
11
Create Invoice → Person

The DRAFT card is the one confirmation

CreateInvoiceIntent.perform()try await requestConfirmation(
  actionName: .custom(acceptLabel: "Create Invoice", acceptAlternatives: ["Yes", "Create it", "Send it"],
                      denyLabel: "Cancel", denyAlternatives: ["No", "Don't create it"], destructive: false),
  dialog: "Create an invoice for \(client) for \(Invoice.format(amount)) for \(work.lowercased())?",
  snippetIntent: InvoiceDraftSnippetIntent(clientName: client, service: work, amount: amount)
)

The card shows the next number (INV-0008), “Bill to John Carter” in green with a leaf, because “gardening” picks that theme, and the due date two weeks out.

The card may not appear with Siri AI Apple notes that the new Siri might not display an app's dialog or card. The confirmation still happens; Siri may ask in its own words. From Shortcuts or “Create an invoice in Skyway” the card always shows.
12
Create Invoice → InvoiceStore

INV-0008 is saved

CreateInvoiceIntent.perform() → App/InvoiceStore.swiftlet invoice = InvoiceStore.createInvoice(clientName: client, service: work, amount: amount)
// INV-0008 · John Carter · Gardening · $450 · issued Nov 9 · due Nov 23

It's now the newest invoice, so the next “bill John the usual” will find it first.

13
Create Invoice → Siri → Person

The result: ISSUED, with View Invoice and Undo

CreateInvoiceIntent.perform()return .result(
  value: invoice.entity,
  dialog: "Created invoice \(invoice.number) for \(client): \(invoice.amountText) for \(work.lowercased()), due \(due).",
  snippetIntent: InvoiceCreatedSnippetIntent(invoice: invoice)

From here everything works as in the Create Invoice guide: Undo voids it in place, and View Invoice opens it in Skyway.

BoundariesWhat's Skyway's code and what's Siri's

Skyway decides

  • What the tools are, and their titles and descriptions
  • Which invoices Get Recent Invoices returns, and which fields
  • Checking the values, the DRAFT card, numbering, saving
  • The skill's rules: look first, full names, the last amount, never guess, no duplicates, dollars only

Siri decides

  • That the request is for Skyway and the invoicing skill applies
  • Matching “John” to John Carter and “the usual” to $450, by following the skill
  • The arithmetic for rates, like 3 × $40
  • How it phrases things, and whether it shows the card or speaks

How Siri matches skills and tools internally isn't public. This describes the behavior Apple documents for Xcode 27.3.

Testing it Needs a real iPhone with Apple Intelligence on iOS 27.3. Create an invoice or two first so there's history, then try “In Skyway, bill John the usual”. Check that Skyway.app/Metadata.appintents/Skills.skillsc exists in the build.
