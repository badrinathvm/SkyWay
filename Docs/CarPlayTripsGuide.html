Chapter 2Project setup: plist and entitlements

Before any Swift runs, three settings tell iOS that Skyway has a CarPlay screen and may use location in the background.

① Scene manifest: “this app has a CarPlay scene”

Project.json → Info.plist"UIApplicationSceneManifest": {
  "UIApplicationSupportsMultipleScenes": true,
  "UISceneConfigurations": {
    "CPTemplateApplicationSceneSessionRoleApplication": [{
      "UISceneClassName": "CPTemplateApplicationScene",
      "UISceneConfigurationName": "CarPlay",
      "UISceneDelegateClassName": "$(PRODUCT_MODULE_NAME).CarPlaySceneDelegate"
    }]
  }
}
  • Session role CPTemplateApplicationSceneSessionRoleApplication means “a scene for the car's main display”.
  • Scene class is always CPTemplateApplicationScene for template-based CarPlay apps.
  • Delegate class is found by name at runtime, so the module prefix matters. If it's wrong, the car screen stays blank with no compile error.
  • The iPhone UI is still SwiftUI's WindowGroup. Both scenes live in the same app process.

② Entitlement: “this app is allowed in CarPlay”

App/App-Simulator.entitlements<key>com.apple.developer.carplay-driving-task</key>
<true/>
Why “driving task”?Each CarPlay entitlement category unlocks a fixed set of templates. Driving task apps (for example mileage logs, toll payments, or parking) get: tab bar, list, grid, information, point of interest, alert, and action sheet. They do not get CPMapTemplate or turn-by-turn navigation, which is why the trip map is a CPPointOfInterestTemplate. The simulator entitlements file is only used for simulator builds. For a real car, request the entitlement from Apple and add it to a provisioning profile.

③ Location permission and background mode

Project.json → Info.plist"NSLocationWhenInUseUsageDescription": "Skyway uses your location to measure the miles you drive for mileage deductions.",
"UIBackgroundModes": ["location"]
  • The usage string is shown on the iPhone the first time a trip starts. CarPlay can't show permission prompts.
  • The location background mode, together with CLBackgroundActivitySession, keeps fixes coming while the iPhone is locked in a cupholder.

Chapter 3CarPlay concepts in 2 minutes

  • Templates, not views. You don't write UI for the car. You build CPTemplate objects (a list, a map, an alert) and fill them with data. CarPlay draws them in the car's style, sizes, and colors, which keeps them safe to use while driving.
  • CPInterfaceController is the navigation controller. It's given to you on connect. It has a root template, a push/pop stack on top, and a single modal slot for alerts and action sheets.
  • Taps are closures. Rows, buttons, and alert actions take a handler closure. There's no target/action or SwiftUI binding.
  • Nothing updates on its own. Templates don't observe your model. To change the screen you set new items or sections on an existing template. In this feature, a 5-second timer does that.
  • Limits apply. A tab bar has at most 4–5 tabs, the stack is at most 5 deep, lists have item limits, and text is truncated by the car. Keep strings short.

Chapter 4Connecting: the scene delegate

The order of calls from plugging in to the Trips tab appearing.

1

Driver taps the Skyway icon on the car screen

  • iOS launches the app if needed (even with the iPhone locked), creates a CPTemplateApplicationScene, and creates CarPlaySceneDelegate from the plist name.
2

templateApplicationScene(_:didConnect:)

Delegate call
  • Saves the CPInterfaceController and scene.
  • Creates CarPlayTripsController(interfaceController:). Its init builds an empty CPListTemplate and fills it straight away with refreshList().
  • Builds a CPTabBarTemplate with Trips first, then Flight, Airport, and Checklist.
  • setRootTemplate(tabBar) puts it on the car screen.
3

tripsController.didConnect()

Our code
  • store.resumeTrackingIfNeeded(): if the app was relaunched mid-trip, starts GPS again.
  • If a trip is already active, pushes the map right away (without animation), so the driver goes straight back to it.
  • Starts the 5-second refresh timer.
…driving…
4

templateApplicationScene(_:didDisconnectInterfaceController:)

Delegate call
  • tripsController.didDisconnect() stops its timer and forgets the map.
  • All template references are set to nil. The trip keeps tracking: the store, not the car screen, owns it.
App/CarPlaySceneDelegate.swiftfunc templateApplicationScene(
  _ templateApplicationScene: CPTemplateApplicationScene,
  didConnect interfaceController: CPInterfaceController
) {
  self.interfaceController = interfaceController
  scene = templateApplicationScene

  let tripTemplate = makeTripTemplate()
  let airportTemplate = makeAirportTemplate()
  let tripsController = CarPlayTripsController(interfaceController: interfaceController)
  let tabBar = CPTabBarTemplate(templates: [tripsController.rootTemplate, tripTemplate, airportTemplate, makeChecklistTemplate()])
  ...

Why a separate controller?The delegate already handles three flight tabs. Putting Trips in its own CarPlayTripsController keeps each file about one feature. The delegate only has to create it, put its rootTemplate in the tab bar, and pass on connect and disconnect. Use this pattern for any new CarPlay tab.
Must do: set a root template before didConnect returns, or the car screen stays blank.

Chapter 7CarPlayTripsController, section by section

This file holds all the Trips UI. Each part below is shown as code, followed by what it does and why.

7.1 · Properties and init

App/CarPlayTripsController.swift@MainActor
final class CarPlayTripsController: NSObject {
  let rootTemplate: CPListTemplate
  private weak var interfaceController: CPInterfaceController?
  private let store = DriveTripStore.shared
  private var mapTemplate: CPPointOfInterestTemplate?
  private var cardOpenedAt: Date?
  private var refreshTimer: Timer?
  private var shownListText: [String] = []
  private var isEnding = false

  init(interfaceController: CPInterfaceController) {
    self.interfaceController = interfaceController
    rootTemplate = CPListTemplate(title: "Trips", sections: [])
    rootTemplate.tabTitle = "Trips"
    rootTemplate.tabImage = UIImage(systemName: "car.fill")
    super.init()
    refreshList()
  }
PropertyWhy it exists
rootTemplateThe Trips tab. Created once and kept, so it can be updated in place.
interfaceControllerweak, because the scene delegate owns it. Used to push, pop, and present.
mapTemplateThe trip map while it's on the stack, or nil. Lets refresh update it, and tells us whether it's showing.
cardOpenedAtWhen the driver opened the car's card on the map. Refresh holds off for 30 s so the card doesn't close under their finger.
shownListTextThe text last put in the list, so the list is only replaced when something changed (no flicker).
isEndingTrue while the end sheet is up. Stops a double tap from opening two sheets, and stops refresh from closing the map.

NSObject is needed because it conforms to CPPointOfInterestTemplateDelegate, an Objective-C protocol. @MainActor because CarPlay templates must only be touched on the main thread.

7.2 · Connect / disconnect / refresh

func didConnect() {
  store.resumeTrackingIfNeeded()
  if store.activeTrip != nil {
    showMap(animated: false)
  }
  refreshTimer = Timer.scheduledTimer(withTimeInterval: 5, repeats: true) { [weak self] _ in
    MainActor.assumeIsolated { self?.refresh() }
  }
}

private func refresh() {
  refreshList()
  if store.isLocationDenied {
    showLocationAlert()
  } else if store.activeTrip == nil, mapTemplate != nil, !isEnding {
    leaveMap()            // trip ended elsewhere (e.g. Siri) → close the map
  } else {
    refreshMap()
  }
}

The timer is the only way the car screen learns about changes it didn't cause, like new miles from GPS, or a trip started or ended with Siri. MainActor.assumeIsolated is safe here because a timer scheduled on the main run loop fires on the main thread.

7.4 · Colored icons

private static func icon(_ systemName: String, _ color: UIColor) -> UIImage? {
  let configuration = UIImage.SymbolConfiguration(pointSize: 40, weight: .semibold)
  guard let symbol = UIImage(systemName: systemName, withConfiguration: configuration)?
    .withTintColor(color, renderingMode: .alwaysOriginal) else { return nil }
  return UIGraphicsImageRenderer(size: symbol.size).image { _ in symbol.draw(at: .zero) }
}

CarPlay re-tints SF Symbols to its own colors. Drawing the symbol into a plain bitmap keeps the blue, brown, or red. statusDot draws a small green circle in the middle of a 40×40 image so CarPlay doesn't scale it up.

7.5 · Starting a trip and showing the map

private func startOrShowTrip() {
  if store.activeTrip == nil {
    store.startTrip()
    refreshList()
  }
  showMap(animated: true)
}

private func showMap(animated: Bool) {
  if let mapTemplate, interfaceController?.topTemplate === mapTemplate { return }
  let template = CPPointOfInterestTemplate(title: "Trip in Progress",
                                           pointsOfInterest: carPoints(), selectedIndex: NSNotFound)
  template.pointOfInterestDelegate = self
  template.trailingNavigationBarButtons = [
    CPBarButton(title: "End Trip") { [weak self] _ in self?.confirmEnd() },
  ]
  mapTemplate = template
  interfaceController?.pushTemplate(template, animated: animated, completion: nil)
}
  • The duplicate-push guard checks topTemplate, not just mapTemplate != nil. The Back button pops the map without telling us, so mapTemplate can point to a map that's no longer on screen.
  • End Trip is in the navigation bar (CPBarButton), so it's there even before the first GPS fix puts the car on the map.
  • selectedIndex: NSNotFound starts with nothing selected.

A CPPointOfInterestTemplate shows a map with pins, plus a side panel with one row per pin. Tapping a row opens a card using the detail* fields and up to two buttons. There's exactly one point, the car, so the trip reads as one row. The 🟢 emoji works as a colored status light, since CarPlay text is always one color.

7.7 · Updating the map without closing the card

private func refreshMap() {
  guard let mapTemplate else { return }
  if let cardOpenedAt, Date.now.timeIntervalSince(cardOpenedAt) < 30 { return }
  cardOpenedAt = nil
  mapTemplate.setPointsOfInterest(carPoints(), selectedIndex: NSNotFound)
}

// CPPointOfInterestTemplateDelegate
nonisolated func pointOfInterestTemplate(_: CPPointOfInterestTemplate, didSelectPointOfInterest _: CPPointOfInterest) {
  let openedAt = Date.now
  Task { @MainActor [weak self] in self?.cardOpenedAt = openedAt }
}

The only way to move the pin or change its text is to replace the points with setPointsOfInterest, and that closes any open card. So when the driver opens the card, refreshes pause for 30 seconds to give them time to tap End Trip. The delegate is nonisolated and hops to the main actor with a Task, because CarPlay may call it from another thread.

7.8 · Ending: confirmEnd() and finish(as:)

private func confirmEnd() {
  guard store.activeTrip != nil, !isEnding else { return }
  isEnding = true
  Task { [weak self] in
    guard let self else { return }
    let address = await store.endingAddress()          // reverse-geocode where we are
    guard var trip = store.activeTrip else { isEnding = false; return }
    let endDate = Date.now
    trip.endDate = endDate                                 // freeze what the sheet shows
    let business = CPAlertAction(title: "Business (\(trip.estimatedDeductionText))", style: .default) { ... finish(as: .business, miles: trip.miles, endDate: endDate) }
    let personal = CPAlertAction(title: "Personal", style: .default) { ... finish(as: .personal, ...) }
    let keepDriving = CPAlertAction(title: "Keep Driving", style: .cancel) { ... isEnding = false; dismissTemplate }
    let sheet = CPActionSheetTemplate(title: "Trip Ended · \(trip.milesText) · \(trip.minutesText())",
                                      message: message, actions: [business, personal, keepDriving])
    interfaceController?.presentTemplate(sheet, animated: true, completion: nil)
  }
}

private func finish(as purpose: DriveTrip.Purpose, miles: Double, endDate: Date) {
  interfaceController?.dismissTemplate(animated: true, completion: nil)   // close sheet
  store.endTrip(as: purpose, miles: miles, endDate: endDate)                // save
  isEnding = false
  leaveMap()                                                                // pop to the list
  refreshList()
}
  • The address lookup is async, so this runs in a Task. isEnding is set first so a second tap is ignored.
  • The miles and end time are captured when the sheet opens. The car may keep moving while the driver decides, but the saved trip matches the numbers on the sheet.
  • presentTemplate shows the sheet modally, and dismissTemplate closes it. Only one modal can show at a time.
  • One question (“Business or Personal?”) both ends the trip and files it, so ending takes one tap plus one choice.

Chapter 9Keeping the car screen current

What happens on every 5-second tick:

⏱

Timer fires → refresh()

1

refreshList()

  • Rebuilds the rows, compares their text with shownListText, and only calls updateSections if something changed.
2

Then the first of these that's true:

ConditionAction
store.isLocationDeniedshowLocationAlert() closes the map and shows the alert
No active trip, map open, not endingleaveMap(): the trip was ended with Siri
OtherwiserefreshMap() moves the car and updates the miles (unless the card was opened in the last 30 s)
Why poll instead of observing?DriveTripStore is @Observable, which suits SwiftUI on the iPhone. CarPlay templates aren't views and don't re-render, so something has to push new data into them. A 5 s timer is simple, picks up changes from any source (GPS, Siri, relaunch), and is cheap because the list only updates when its text changes.

10.2 · From GPS to miles

App/DriveTracker.swiftserviceSession = CLServiceSession(authorization: .whenInUse)   // asks for permission on iPhone

for try await update in CLLocationUpdate.liveUpdates(.automotiveNavigation) {
  if update.authorizationDenied || update.authorizationDeniedGlobally || update.authorizationRestricted {
    continuation.yield(.denied); break
  }
  if let location = update.location, location.horizontalAccuracy >= 0, location.horizontalAccuracy <= 50 {
    continuation.yield(.location(location))
  }
}
  • Why the filters? Bad GPS fixes wander around. Without filtering, a phone sitting in a parking lot would slowly add up miles. Skipping moves under 5 m also keeps the older fix, so a slow crawl still adds up once it passes 5 m.
  • The tracker exposes an AsyncStream<Event>. The store reads it with for await in a Task, and cancelling that task stops the stream.
  • -simulateDrive (DEBUG only) swaps in SimulatedDrive, which drives through Cupertino at about 67 mph.

10.3 · Saving

The store writes { trips, activeTrip } as JSON to Application Support/DriveTrips.json. It uses .completeFileProtectionUntilFirstUserAuthentication because CarPlay usually runs with the iPhone locked. Stricter protection would make the file unreadable while driving. Because the active trip is saved too, a trip survives the app being killed. On relaunch, didConnect() → resumeTrackingIfNeeded() picks it back up.

10.4 · DriveTrip: the model

A Codable struct with startDate, endDate, start/end coordinates, addresses, miles, and an optional purpose. It also builds all the display text, such as milesText (“14.2 mi”), summaryText (“Today 8:12 AM · 14.2 mi · Business · $2.27”), and routeText. Keeping text formatting in the model means the CarPlay code and Siri replies always match. The deduction is miles × $0.16 and only counts for .business trips.

Chapter 14Testing in the simulator

Option A, built-in fake drive: turn on the -simulateDrive launch argument in the scheme (Project.json → commandLineArguments). DriveTracker then plays back a drive through Cupertino at about 67 mph and parks at the end.

Option B, simulated location: start a trip in CarPlay, then run

Scripts/simulate-drive.sh          # 7.5 mi through Cupertino at 30 mph
Scripts/simulate-drive.sh 70       # same route at 70 mph
Scripts/simulate-drive.sh freeway  # Apple's Freeway Drive scenario
Scripts/simulate-drive.sh stop     # stop and clear

This uses xcrun simctl location on the booted Bitrig iPhone simulator, so it tests the real CoreLocation path, including the permission prompt.

Chapter 15Gotchas we hit

  1. Back doesn't tell you. Popping with the system Back button doesn't notify your code. Check interfaceController.topTemplate before deciding a template is still showing.
  2. Replacing points closes the card. setPointsOfInterest is the only way to update a pin, and it closes an open card. Hold off refreshes while the driver is reading it.
  3. Selecting from code isn't “opening the card”. Passing a selectedIndex only highlights the row, and may trigger the selection delegate as if the driver tapped. Use NSNotFound.
  4. Colors get stripped. CarPlay re-tints text and symbols. Draw icons into bitmaps, or use emoji, for color.
  5. Always call completion() in a CPListItem.handler, or the row spins forever.
  6. Freeze values shown in a sheet. Data keeps changing while a modal is up. Save what the driver saw.
  7. File protection vs. a locked phone. Use …UntilFirstUserAuthentication for anything CarPlay reads or writes.
  8. Short strings. Side-panel rows truncate early, which is why the status became “🟢 Parked” and not a longer phrase.
  9. Don't rebuild templates on every tick. Compare first, then update in place (updateSections), to avoid flicker and stay within CarPlay's update limits.

Adding a new CarPlay tab: checklist

  1. Check that your entitlement category allows the templates you need.
  2. Put the data and logic in a shared @MainActor store, not in the CarPlay code.
  3. Create a CarPlayXController with a rootTemplate, didConnect(), and didDisconnect().
  4. Give the root template a tabTitle and tabImage, and add it to the CPTabBarTemplate in CarPlaySceneDelegate.
  5. Keep a strong reference to the controller in the delegate, and release it on disconnect.
  6. Refresh by updating templates in place, with a timer or store callbacks.
  7. Add any permissions to Info.plist. Prompts appear on the iPhone, not the car.
