App Store Retention Messaging

How the "Confirm Cancellation" message works, who decides what it says, and where to click in App Store Connect. Written for Skyway Plus, the mock subscription in this project.

1 · Big picture 2 · What you control 3 · The flow 4 · Which setup? 5 · App Store Connect steps 6 · Real-time server 7 · In the app 8 · Testing 9 · Limits & languages 10 · Content rules
The one thing to remember The cancellation sheet is Apple's screen. Your words and pictures are uploaded to Apple ahead of time and approved by App Review. At most, a server you run picks which uploaded message to show. Your app never draws this screen.

1 · The big picture

Three players. Only the first is required.

✎

App Store Connect Required

Where messages live.
  • Header, body, bullet points
  • Optional image (Asset Library)
  • Optional Retention Offers
  • Link to subscriptions
  • Submitted for review
⚙︎

Your server Optional

Picks a message per subscriber, in real time.
  • Apple calls it when someone may cancel
  • Replies with a message ID
  • Can suggest another plan or a promotional offer
  • Must answer within 700 ms
  • Access by request to Apple
✈︎

Skyway app Your code

Sells the plan and reacts to the result.
  • Sells Monthly / Annual (StoreKit 2)
  • Opens Apple's manage sheet
  • Reads the resulting transactions
  • Spots offer type 5 (Retention Offer)

"From the Developer" card: yours. Header, body, bullets, and optional image come from the message you uploaded. A Switch Plan or Accept Offer button appears here when your message has an offer or plan suggestion. Apple writes the price on that button, not you.

4 · Which setup do you need?

Simple App Store Connect only

  • One message per subscription, the same for everyone
  • Text, text + image, or text + Retention Offer
  • Apple decides who is eligible for offers
  • No backend, no access request

Good for: most apps. Skyway could start here with "Keep your mileage log".

Advanced Real-time server

  • A different message per subscriber
  • Switch-plan suggestions (Monthly → Annual)
  • Your own offer eligibility rules + signed promotional offers
  • Needs JWS verification, a 700 ms deadline, a performance test, and Apple's approval

Good for: when you already know your subscribers (Skyway knows who logs CarPlay drives).

Illustration only. Apple's real page may be laid out differently, but the fields and steps are the same.

  1. Have an auto-renewable subscription. Skyway Plus Monthly and Annual must exist as real products in the "Skyway Plus" group. Today they only exist in the local test file StoreKit/SkywayPlus.storekit.
  2. Open Retention Messaging using the path above, then choose Get Started.
  3. Write the message.
    • Reference name: internal only (e.g. "Keep mileage log").
    • Header and body: what subscribers read. Bullet points are allowed.
    • Add localizations for each language you support.
  4. Optionally add an image from the App Store Connect Asset Library. This is what makes it a "text + image" message.
  5. Optionally add Retention Offers: a discounted price or free period (Pay as you go, Pay up front, or Free). Set eligibility:
    • Paid Subscription Duration: how long someone must have paid before they qualify.
    • Wait Between Offers: how long before the same offer can be redeemed again.
    Up to 10 offers per billing plan type. Apple picks which eligible one to show.
  6. Link it to subscriptions. Each subscription can have one message at a time. One message can cover several subscriptions. Up to 10 messages per app on the website, or 2000 through the API. Without a real-time server, the linked message is the one subscribers see; other approved messages wait until you link them.
  7. Submit for review. Sandbox testers can see drafts before approval.
  8. Changing it later: edit and resubmit. The approved version stays live until the new one is approved. No app update needed.
Prefer scripts over clicking? The same setup is available from the Retention Messaging API: Upload Image, Upload Message (header, body, bullets, image ID), and Configure Default Message for the fallback.

6 · Adding a real-time server

Only if you want per-subscriber choices. All configuration here is done through the API, not the website.

  1. Request access to the real-time Retention Messaging API from Apple.
  2. Upload every message you might pick (section 5, or Upload Message), and wait for approval. Your server can only point to approved messages by ID.
  3. Build the endpoint. Apple sends {"signedPayload": "<JWS>"}. Verify it, decode it, decide, then reply: 
    // Show a message (text, or text + image)
{ "message": { "messageIdentifier": "6a1f3b2e-…" } }

// Suggest another plan in the group
{ "alternateProduct": { "messageIdentifier": "ed7f25fc-…", "productId": "skyway.plus.annual" } }

// Promotional offer, signed by your server
{ "promotionalOffer": { "messageIdentifier": "c4d9e1a7-…", "promotionalOfferSignatureV2": "<JWS>" } }
  4. Point Sandbox at it with Configure Realtime URL.
  5. Pass the performance test (Initiate Performance Test, then Get Performance Test Results). It proves you answer within 700 ms.
  6. Configure the production URL, then watch the App Store Retention Messaging analytics report.

Leave room for translations German and French often run 30–40% longer than English. A 60-character English header may not fit in German. Apple doesn't publish a maximum number of bullets (only a "too many bullet points" error), so keep to about five.

  • PNG, no transparency. Bake the colored rounded square into the image. Check it in light and dark mode.
  • Each image is reviewed separately. The message shows only once the message and all its images are approved.
  • Only text messages get images or bullets. Switch-plan and promotional-offer messages are text only.
  • Per-bullet icons are documented for the API (Upload Image, then Upload Message). The website editor may not offer them.
  • Emoji: not mentioned in Apple's docs, and App Review judges content. Use bullet images instead, as above. The icons in this example are drawings only.

Languages, not countries

How it works

  • One message per subscription per language. Countries that share a language share its message.
  • You don't have to translate into every language. Cover the ones your app and App Store page support.
  • Apple doesn't document what an uncovered language sees. Most likely it's the plain sheet with no "From the Developer" card.

With a real-time server

  • Apple requires a default message for every subscription in every language you serve in real time.
  • Set them with Configure Default Message, one call per product and locale.
  • API limits: 2000 messages and 2000 images per app.
  • Sandbox approves API uploads automatically, so you can test straight away.

10 · Content rules (or App Review rejects it)

Don't write

  • Prices: "$9.99"
  • Discounts: "50% off"
  • Promotions: "one month free"
  • Pressure: "Last chance!", "You'll regret it"
  • Claims you can't back up

Do write

  • Features they'll lose, if accurate: "Skyway stops logging drives from CarPlay"
  • What's coming next
  • Leave the offer terms to Apple's offer button
